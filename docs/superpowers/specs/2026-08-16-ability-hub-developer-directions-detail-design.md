# Ability Hub 程序员开发方向与项目详情页设计

**状态：** 用户已确认设计方向，待实施计划与编码。

## 目标

让第一次使用 DeepSeek Harness 的用户能够：

1. 在“程序员”行业下，按真实开发方向寻找 GitHub 项目，而不是理解“Skill、MCP、插件、工作流”等实现术语。
2. 点击任意项目卡片后立即进入可见的独立详情页。
3. 在详情页直接看懂项目用途、GitHub 地址、接入方式、风险边界和移除方法。
4. 在不自动安装远程代码的前提下，让 DeepSeek Harness 创造模式帮助用户生成适配方案。

## 已确认的问题

当前卡片点击事件本身有效，选中卡片会出现蓝色边框。问题是 `AbilityDetail` 被渲染在完整项目网格之后；“程序员”当前有 54 个项目，因此详情出现在全部卡片的最底部，用户会认为点击没有反应。

修复不能只增加自动滚动。正确设计是让列表和详情成为两个互斥页面状态，点击后用详情页替换列表。

## 范围

### 本次包含

- “程序员”行业专用的七个开发方向。
- 程序员项目的人工归类规则与完整性校验。
- 能力库列表页的简化卡片。
- 替换列表的项目详情页。
- 返回列表时保留搜索、筛选和浏览位置。
- GitHub 外部链接、创造模式适配入口、兼容提示和移除说明。
- 回归测试、目录数据测试、类型检查和桌面构建验证。

### 本次不包含

- 自动下载、安装或执行 GitHub 仓库代码。
- 为金融、医疗、生命科学、零售、政府或教育重新设计行业专属分类。
- GitHub 登录、收藏、评分、评论或在线市场后端。
- 修改 DeepSeek Harness 官方聊天页面或官方扩展协议。
- 为每个项目制作自有品牌图标；继续使用 GitHub 头像并保留首字母回退。

## 信息架构

能力库保留两层导航：

1. 第一层是“行业”。
2. 当行业选择“程序员”时，第二层从通用“种类”切换为“开发方向”。

其他行业和“全部行业”暂时沿用现有通用能力种类，不在本次范围内重构。

### 程序员开发方向

| ID | 用户标签 | 收录范围 | 典型项目 |
| --- | --- | --- | --- |
| `development-process` | 开发流程 | 需求澄清、规划、TDD、调试、代码审查、架构设计、代码简化和开发期质量反馈 | obra/superpowers、mattpocock/skills、Ponytail、pi-lens |
| `frontend` | 前端 | 网页、React、UI/UX、样式、无障碍、界面扩展、视觉还原 | frontend-design、DSH UI 扩展、DSH Vision Toolkit |
| `backend` | 后端 | API、服务端、数据库、鉴权、支付和第三方服务集成 | stripe/ai、mcp-use，以及后续加入的后端项目 |
| `crawler` | 爬虫 | 搜索、网页抓取、浏览器自动化、公开资料研究和网页测试 | Agent-Reach、Firecrawl、Playwright、Playwright MCP、browser-use、last30days |
| `agent-workflow` | Agent 与工作流 | Skill、MCP、Preset、子 Agent、记忆、上下文、模型路由和任务编排 | DSH 官方扩展配方、pi-subagents、pi-hermes-memory、pi-context、Composio |
| `data-ai` | 数据与 AI | 文件解析、OCR、数据处理、RAG、知识图谱、模型文档和 AI 数据工具 | MarkItDown、PaddleOCR、Context7、LLM Wiki、DSH Knowledge Graph |
| `operations` | 运维 | 生产监控、安全、插件审计、回归评测、CI/CD、发布和回滚 | Sentry MCP、DSH Plugin Audit、DSH Eval Harness、Security Skill Pack |

### 分类边界

- 开发过程中使用的规划、TDD、调试和代码审查归“开发流程”。
- 上线后的监控、安全、插件审计和持续回归归“运维”。
- 浏览器操作、网页测试、搜索和抓取优先归“爬虫”，即使项目也能用于前端测试。
- Skill、MCP、插件、Preset、UI 扩展和工作流是“扩展类型标签”，不是开发方向。
- 一个项目可以属于多个开发方向；数组第一项是卡片显示的主要方向，其余方向用于筛选发现。
- 分类必须由目录数据明确声明，不在运行时根据标题或关键词自动猜测。

## 数据模型

新增类型：

```ts
export type DeveloperDirectionId =
  | 'development-process'
  | 'frontend'
  | 'backend'
  | 'crawler'
  | 'agent-workflow'
  | 'data-ai'
  | 'operations'
```

`AbilityDefinition` 新增必填字段：

```ts
readonly developerDirectionIds: readonly DeveloperDirectionId[]
```

数据约束：

- 所有包含 `programmer` 行业的项目至少拥有一个开发方向。
- 非程序员项目可以使用空数组。
- `developerDirectionIds[0]` 是卡片主要方向。
- 项目详情继续使用现有 `summary`、`outcome`、`userProvides`、`userReceives`、`readsOrChanges`、`rollback`、`addMethod`、`repositoryUrl` 和许可证字段。
- GitHub URL 仍是目录项目的必填字段。

筛选状态新增 `developerDirection`。进入“程序员”时，通用种类重置为 `all`；离开“程序员”时，开发方向重置为 `all`。这样隐藏的筛选条件不会继续影响当前结果。

开发方向筛选匹配 `developerDirectionIds` 中任意一项，因此跨方向项目可以从多个入口找到，但卡片只显示数组第一项作为主要方向。

## 列表页设计

### 筛选区

当选择“程序员”时显示：

```text
行业：全部行业｜程序员｜金融服务｜医疗健康｜……
开发方向：全部方向｜开发流程｜前端｜后端｜爬虫｜Agent 与工作流｜数据与 AI｜运维
```

“程序员”未选中时不显示这七项，继续使用原有通用种类。

搜索与开发方向同时生效。结果数量显示当前过滤后的项目数。

### 项目卡片

卡片保持两列布局，整张卡片可点击，并支持键盘 Enter 和 Space。

每张卡片只展示：

- GitHub 头像或首字母回退。
- 仓库名称。
- 一句普通话用途说明。
- 主要开发方向。
- 扩展类型，例如 Skill、MCP、插件或工作流。
- 来源可信度。
- “查看详情”入口。

不在卡片重复展示完整简介、兼容说明和安装方法，避免信息过密。

## 详情页设计

### 页面状态

能力 Hub 只有两个互斥状态：

- `list`：显示搜索、筛选和项目网格。
- `detail:<abilityId>`：隐藏网格，显示选中项目详情。

详情页不是新浏览器窗口，也不追加在列表底部；它在同一个白色 Ability Hub 容器中替换列表内容。

### 进入详情

- 点击卡片任意非交互区域或“查看详情”进入。
- 进入前保存当前 Ability Hub 滚动位置。
- 页面切换后将详情标题滚动到可见区域并获得合理的键盘焦点。
- 详情数据从完整目录按 ID 读取，不依赖当前过滤结果。

### 返回列表

- 顶部固定提供“← 返回能力库”。
- Escape 键也可以返回。
- 返回后恢复搜索词、行业、开发方向、通用种类和原来的滚动位置。
- 原卡片恢复可见并保持键盘焦点。

### 详情内容

详情页按以下顺序展示，关键内容不放入折叠区：

1. 返回能力库。
2. GitHub 头像、仓库名称、一句话用途。
3. 开发方向、扩展类型、来源可信度和兼容方式。
4. “项目简介”：合并用途与简明介绍，使用普通话说明。
5. “GitHub 仓库”：显示完整 URL 和“打开仓库”按钮。
6. “适合你如果”：说明适用场景、用户需要准备什么和最终得到什么。
7. “怎么加入 DeepSeek Harness”：直接展示 `addMethod`，不再藏在高级信息。
8. “权限、风险与移除”：展示读取/修改范围、兼容警告和 `rollback`。
9. 操作区。

安全创建 Prompt 可以保留在页面底部的“查看创建说明”折叠区，因为它不是用户判断项目时的必要内容。

### 操作区

- “打开 GitHub”：通过 Electron 的外部链接处理器打开系统默认浏览器。
- 原生或可直接配置的项目显示“让 DeepSeek 帮我添加”。
- `manual-adapter` 项目显示“让 DeepSeek 帮我适配”，并明确说明不能直接安装。
- “先问 AI 是否适合我”保留为次级操作。
- 所有创造按钮仍只复制安全说明并打开创造模式，不自动发送、不自动安装。

## 视觉规则

- 延续当前白底、浅灰边框和低饱和蓝色强调色。
- 详情页使用单一主容器，不使用右侧抽屉或悬浮弹窗。
- 内容最大宽度与能力库一致，正文阅读宽度受限，避免整行过长。
- GitHub 地址使用等宽字体，但允许换行，不能在窄屏被截断到不可识别。
- 主要按钮最多两个；“打开 GitHub”和创建/适配是主操作，AI 顾问为次级操作。
- 不使用大面积渐变、装饰插画或多层卡片嵌套。

## 异常与边界处理

- GitHub 头像加载失败时显示首字母图标，不能影响卡片和详情。
- 目录构建阶段发现程序员项目缺少开发方向、GitHub URL 或简介时测试失败。
- 项目为 `manual-adapter` 时必须显示兼容警告，禁止出现“直接安装”措辞。
- 创造模式不可用时，GitHub 浏览和项目说明仍可使用；创建按钮禁用并说明去“设置 → Agent 预设”恢复。
- 外部仓库失效或返回 404 不由桌面端自动替换来源；后续目录维护时更新。
- 搜索或筛选没有结果时显示清除条件和 AI 顾问入口。

## 测试与验收

### 目录测试

- 七个开发方向 ID、标签和顺序固定。
- 每个程序员项目至少有一个有效开发方向。
- 七个方向均至少有一个项目。
- 所有目录项目具有有效 GitHub URL、普通话简介、添加方法和移除方法。

### 组件测试

- 点击卡片后项目网格从 DOM 中移除，详情页立即出现。
- 详情页直接显示完整 GitHub URL、项目简介和添加方法，不需要展开高级信息。
- 点击返回后恢复搜索、筛选和列表。
- 整张卡片、Enter 和 Space 均能进入详情；Escape 能返回。
- `manual-adapter` 使用“帮我适配”和兼容警告。
- 切换离开程序员行业时开发方向重置。

### 集成验证

- Creator Center 全部测试通过。
- TypeScript 类型检查通过。
- Creator Center 构建成功并更新已跟踪的 `lib` 产物。
- 根桌面测试通过。
- 启动最新版桌面 GUI，人工验证列表 → 详情 → GitHub → 返回列表的完整路径。

## 成功标准

- 用户点击第一屏任意项目后，不需要滚动即可看到详情页。
- 用户不理解 Skill、MCP 或插件，也能通过七个开发方向找到项目。
- 详情页首屏可以回答“这是做什么的、仓库在哪里、能不能直接加”。
- 返回列表后没有丢失用户原来的查找位置。
- 不引入自动安装远程代码的新风险。
