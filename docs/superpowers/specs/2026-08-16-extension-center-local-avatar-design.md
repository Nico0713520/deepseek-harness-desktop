# 扩展中心本地 GitHub 图标与侧栏统一设计

## 目标

消除能力卡片依赖 GitHub 远程图片造成的 0.9–10.6 秒可感知延迟，同时完整保留用户确认最好看的原版图标：个人仓库显示作者头像，组织仓库显示组织 Logo。

## 设计

- 构建脚本获取每个 GitHub RepositoryOwner 的公开头像，保持原版卡片的图标选择逻辑。
- 所有图标压成 32×32 缩略图，合并成一张压缩 JPEG 精灵图并内联到插件包；运行时不发起任何远程图片请求。
- 没有可靠图标的仓库显示项目名首字母。
- 左侧“能力中心”改名“扩展中心”。三个入口继续保持 252×38、12px 圆角、白底和官方灰色边框。
- 当前入口不再使用蓝色边框和加粗字体，只用轻微灰底提示选中状态；无障碍状态继续由 `aria-current="page"` 提供。
- Pi 项目在卡片来源行标成“Pi 热门扩展 · 高阶定制参考”。详情页说明它适合高阶开发者借鉴，并通过 Harness 的 Skill、MCP、Preset 或插件机制实现等价能力，不误导为可直接安装。

## 性能验收

- 扩展中心卡片网格不引用任何远程图片 URL。
- 打开扩展中心后，不产生 `github.com/*.png` 或 `avatars.githubusercontent.com` 图片请求。
- 卡片首屏立即显示本地组织 Logo 或字母回退，不发生图片替换和布局跳动。

## 测试

- 组件测试验证入口名称为“扩展中心”。
- 组件测试验证个人和组织仓库都使用本地 `data:image/jpeg` 精灵图，且不存在远程图片 URL。
- 组件测试验证 Pi 项目显示高阶定制文案，详情页显示 Pi 适配说明。
- 运行插件包测试、类型检查、构建和真实页面网络复测。
