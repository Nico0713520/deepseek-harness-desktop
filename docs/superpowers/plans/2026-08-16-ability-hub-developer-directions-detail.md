# Ability Hub 开发方向与详情页实施计划

> **给执行者：** 在当前工作区按任务顺序执行；每项完成后勾选对应复选框。

## 目标

把能力中心从“点击后只出现选中边框、详情藏在列表底部”改成真正可用的资源目录：

- 程序员行业使用七个清晰的开发方向筛选：开发流程、前端、后端、爬虫、Agent 与工作流、数据与 AI、运维。
- 点击任意能力后，详情页立即替换能力卡片列表，用户在当前视口直接看到项目简介、GitHub 地址和加入方法。
- 保留搜索、筛选和返回后的状态，详情页支持返回能力库与 Escape 退出。
- 卡片信息收敛为方向、扩展类型、可信度和简短用途，减少噪音。

## 约束与技术边界

- 继续使用当前 React + TypeScript + CSS Modules 前端，不改 DeepSeek Harness 核心运行时。
- 目录条目只是推荐/引导，不会自动把第三方 Skill、插件安装到用户环境。
- GitHub 地址、添加方法、兼容性和风险提示必须可见；高级 Prompt 仍可折叠。
- 不引入新的 UI 框架或远程运行时依赖。
- 保留用户当前工作区已有的主题、桌宠和能力中心改动。

## Task 1：建立开发方向领域模型

**文件：** `packages/dsh-creator-center/src/client/developer-directions.ts`、`catalog.ts`、`catalog.test.ts`

- [ ] 定义七个稳定的 `DeveloperDirectionId` 与中文标签。
- [ ] 为全部程序员类目录条目建立显式方向映射；一个项目允许属于多个方向。
- [ ] 将 `developerDirectionIds` 加入 `AbilityDefinition`，并在目录构建时校验默认值。
- [ ] 将方向加入 `AbilityFilters` 与 `abilitiesFor`，保留原有非程序员行业的通用能力种类筛选。
- [ ] 测试七类方向、程序员目录数量、每个程序员条目至少一个方向，以及多方向筛选。

## Task 2：实现动态筛选条

**文件：** `CreatorCenter.tsx`、`AbilityLibrary.tsx`、`CreatorCenter.test.tsx`

- [ ] 进入“程序员”行业时显示“开发方向”筛选，隐藏通用“能力种类”筛选。
- [ ] 离开“程序员”行业时恢复原有通用能力种类筛选。
- [ ] 切换筛选时清理当前详情选择，避免显示已不匹配的条目。
- [ ] 进入程序员行业时重置通用种类；离开时重置开发方向。
- [ ] 为筛选按钮补充可访问的分组名称和选中状态测试。

## Task 3：让详情页替换列表并完善内容

**文件：** `AbilityLibrary.tsx`、`AbilityDetail.tsx`、`creator-center.module.css`

- [ ] 将详情渲染移到列表分支之前，选中时不再渲染完整卡片网格。
- [ ] 详情页提供唯一的“返回能力库”入口，显示标题、简介、GitHub URL、打开仓库按钮、兼容性与风险。
- [ ] 将“怎么加入 DeepSeek Harness”从高级折叠区移到首屏；高级区只保留补充实现细节和生成 Prompt。
- [ ] 点击卡片、详情按钮、Enter/Space 都进入详情；Escape 返回列表。
- [ ] 进入详情后滚动到详情区域，保留筛选条件和搜索词。
- [ ] 调整卡片和详情页层级，减少重复标签，保持当前浅色 DeepSeek UI 的留白和对齐。

## Task 4：验证与交付

- [ ] 更新并运行 creator-center 单元测试，覆盖“详情不与网格同时存在”。
- [ ] 运行类型检查、构建、根目录测试和 `git diff --check`。
- [ ] 启动本地 GUI，手动验证：程序员七类筛选、卡片进入详情、GitHub 链接、返回、Escape，以及非程序员筛选不回归。
- [ ] 记录未实现的后续项：远程目录同步、真正的一键安装、第三方资产授权审核。

## 验收标准

1. 点击任意卡片后，当前视口立即出现详情，不需要滚到全部卡片底部。
2. 程序员行业只出现七个开发方向，且每个方向能筛出对应项目。
3. 详情页能直接看懂“这是做什么、去哪里看、怎么加入、有什么风险”。
4. 返回能力库后，搜索词和筛选条件不丢失；原有主题/桌宠和聊天功能不受影响。
5. 测试、类型检查和构建全部通过。
